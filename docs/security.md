# Threat table

The harness's security properties, each with the tests that prove it
(statewalker/statewalker-root#85). A row names its tests as `` `<package>`: "<test title>" ``,
separated by `;`. `ai-conformance`'s threat-table test fails CI when a row names no test or a test
that does not exist. Every ticket that touches a security property adds or extends its row.

| Property | Tests |
|---|---|

| Ignore rules (the deployment's defaults and each project's `.system/ignore`, gitignore syntax) hide files from agent sessions and their tool calls (ENOENT, absent from listings, never removed or overwritten by them), never from the user's own session; they only narrow, and a negation cannot bring back a file under an ignored folder | `ai-conformance`: "hides files the ignore rules name from agent sessions, but not from the user's own session"; `ai-environment`: "hide matching files and folders from a holder given them"; `ai-environment`: "hide nothing from a holder without them"; `ai-environment`: "only narrow: a negation cannot bring back a file under an ignored folder" |

| Tenancy: a Workspace DO never calls a User DO; the gate takes user, project and session from the capability alone and answers while the User DO is unreachable | `ai-conformance`: "the gate answers an agent session's file calls while its User DO is unreachable"; `ai-conformance`: "a Workspace DO holds no way to call a User DO or the profiles" |

| Erasing a user erases their profile and their User DO's storage, and no other user's | `ai-conformance`: "erasing a user erases their profile and their User DO's storage" |
| Modes and permission rules decide every action at that moment, after the roles, and a folder's removal for every entry inside it: a mode switch reaches a running agent session at its next call; deny beats ask and ask beats allow across the deployment's, project's, user's, session's and mode's rules; `dontAsk` denies what no allow rule allows, `bypassPermissions` never asks but a deny rule still denies, `plan` writes only in its folders, `auto` is `default` | `ai-conformance`: "a mode switch reaches a running session at its next action"; `ai-conformance`: "decides by the rules of the deployment, the project, the user and the mode: deny beats ask, ask beats allow"; `ai-conformance`: "decides a folder's removal by every entry inside it: a denied or asking file inside denies or asks"; `ai-access`: "deny beats ask and ask beats allow, whichever layer holds each"; `ai-access`: "dontAsk never prompts: allow rules run, everything else is denied"; `ai-access`: "bypassPermissions never asks, and a deny rule still denies"; `ai-access`: "plan writes only in its configured folders and asks to widen or switch elsewhere"; `ai-access`: "treats auto as default until the risk classifier"; `ai-access`: "ignores an unknown mode name and malformed rules instead of widening" |
| Only the user switches modes and answers approvals: the gate takes a mode, the user's rules and a granted approval only with a bare user capability (an agent session's is refused), a mode switch needs the user's own access token, and an approval is reached only by its own user | `ai-access`: "takes the user session's own decisions (mode, rules, approvals) only from a bare user capability"; `ai-conformance`: "only the user switches modes, to a mode that exists, for their own sessions"; `ai-conformance`: "an approval is answered only by its own user" |
